# Project vocabulary

Product terms follow [PRD §13](docs/PRD.md#13-glossary). Planned product behavior is
separate from the current infrastructure skeleton.

| Term                          | Meaning                                                                                                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tạp hóa                       | Small neighborhood convenience/grocery store.                                                                                                                                                                 |
| Hộ kinh doanh                 | Household business, the legal form of most tạp hóa.                                                                                                                                                           |
| Thuế khoán                    | Presumptive lump-sum tax described in the PRD as being phased out.                                                                                                                                            |
| VietQR                        | NAPAS interbank QR standard; planned checkout payment QR with an exact amount.                                                                                                                                |
| Enrollment                    | Adding a product to the catalog by photo and price.                                                                                                                                                           |
| Lead                          | Family member who owns prices; a planned application role.                                                                                                                                                    |
| Chốt sổ                       | End-of-day close and cash reconciliation.                                                                                                                                                                     |
| Segmenter                     | Rust trait abstracting image segmentation; API code depends on this interface.                                                                                                                                |
| SAM                           | Segment Anything Model; phase-one ONNX encoder/decoder segmentation adapter.                                                                                                                                  |
| ONNX / ort                    | Portable model format / Rust bindings for ONNX Runtime. Weights and runtime are separate downloads.                                                                                                           |
| YOLO                          | Phase-two detection adapter; currently an unimplemented Segmenter stub.                                                                                                                                       |
| Bounding box                  | Segment rectangle `[x, y, width, height]`, accompanied by score and pixel area.                                                                                                                               |
| pgvector                      | Postgres extension for vector operations; enabled by migration, without product embedding/search features yet.                                                                                                |
| axum / tokio                  | Rust HTTP framework / asynchronous runtime.                                                                                                                                                                   |
| SQLx                          | Rust SQL client and migration tooling.                                                                                                                                                                        |
| Redis                         | Cache/dependency service checked by API readiness.                                                                                                                                                            |
| Health / readiness            | `/healthz` proves the process responds; `/readyz` additionally checks Postgres, Redis and configured object storage.                                                                                          |
| Expo SDK / Expo Router        | Mobile runtime/tooling release / file-based React Native routing.                                                                                                                                             |
| EAS Workflow                  | Expo-hosted YAML automation for native builds and Maestro tests. Config lives under the mobile app.                                                                                                           |
| Maestro                       | Mobile UI smoke-test runner operating on an installed app/device.                                                                                                                                             |
| pnpm workspace / Turborepo    | Package/dependency organization / root task runner across mobile and backend wrappers.                                                                                                                        |
| cargo-chef                    | Docker dependency planning and compilation stages retained as reusable build layers.                                                                                                                          |
| Compose profile               | Optional group of local services; `mobile` adds the Expo development server.                                                                                                                                  |
| Railway service / environment | Deployable app or database / isolated project configuration such as production.                                                                                                                               |
| Railway IaC                   | Railway project graph (services, databases, volumes, variables) tracked in `.railway/railway.ts`.                                                                                                             |
| Model-free image              | `SKIP_MODELS=1`: ONNX Runtime is included, SAM weights are absent, segmentation deliberately returns 503.                                                                                                     |
| Conventional Commits          | Structured Git messages such as `fix: repair readiness check`, enforced by commitlint.                                                                                                                        |
| Object key                    | Stable private-bucket path such as `images/2026/10/<uuid>.png`; persisted in Postgres instead of bytes or a URL.                                                                                              |
| Presigned URL                 | Time-limited signed GET URL for a private image; generated on each API read and never stored.                                                                                                                 |
| Railway Bucket                | Private S3-compatible object storage; the `images` bucket holds photo bytes while Postgres holds references.                                                                                                  |
| Scan                          | Proposed: one recognition request on a photo; stores the photo, detections and candidates. See `docs/architecture.md`.                                                                                        |
| Detection                     | Proposed: one segmented crop in a scan, with top-k product candidates and a match class.                                                                                                                      |
| Manual line                   | Proposed: sale line sold without a catalog match (or at a mismatched price); queued for Lead review.                                                                                                          |
| Outbox                        | Proposed: phone queue of pending writes replayed idempotently; server-side `outbox_events` table for events.                                                                                                  |
| Change feed                   | Proposed: `GET /v1/sync/changes`, cursor-ordered upserts/deletes of server-owned entities for the phone replica.                                                                                              |
| Business date                 | Proposed: calendar date in `Asia/Ho_Chi_Minh` stored on sales/expenses; reports and chốt sổ group by it.                                                                                                      |
| Session (app)                 | A Clerk session on the device (Clerk token cache on `expo-secure-store`); the app sends its session token and `X-Store-Id`. No session means sign-in. Replaced our access + refresh token session (ADR 0004). |
| Recovery code                 | Removed (ADR 0004): Clerk account recovery replaces it, and the backend keeps no recovery code.                                                                                                               |
| Quick enroll                  | Proposed: tag-toggle camera mode; 3..8 photos, each cut out by MobileSAM from 1-2 tapped points. See `docs/specs/quick-enroll.md`.                                                                            |
| Point prompt                  | Proposed: 1-2 tapped pixels (foreground/background label) sent to `POST /v1/segment/points`.                                                                                                                  |
| Cutout                        | Proposed: masked product crop on a neutral grey background, stored as an image and embedded as a reference.                                                                                                   |
| Prototype                     | Proposed: per-product mean of its reference embeddings; few-shot score is `max(best reference, prototype)`.                                                                                                   |
| Index job                     | Proposed: background job that embeds references, recomputes the prototype and emits `product.indexed`.                                                                                                        |
| Test double (mobile)          | `apps/mobile/src/test/mock`, an in-memory fake of the API for Jest only; the app bundle never imports it.                                                                                                     |
| Stock quantity                | Product base-unit count; `NULL` means untracked. Sales subtract, voids and confirmed receipts add; tracked stock may be negative.                                                                             |
| Stock movement                | Ledger row for a receipt, sale, sale void or Lead adjustment, with signed delta and quantity after; committed with the change.                                                                                |
| Low-stock threshold           | Store default (5) or product override (0..100000). `stock.low` fires only on crossing from above to at or below it; restocking above re-arms it.                                                              |
| Import receipt (hóa đơn nhập) | Supplier receipt photo parsed into a draft; confirmation records one nhập hàng expense with purchase lines and adds stock.                                                                                    |
| Receipt line                  | OCR item `{product_name, quantity, cost}` plus product mapping and candidates; cost is the line amount in đồng, quantity is in base units.                                                                    |
| Document detection            | Text detection inside every scan; `document.detected` is true with at least 6 text lines and text area ratio ≥ 0.08.                                                                                          |
| Decision model                | OpenRouter Decisions API for receipt line roles and product mapping; Mercury (`inception/mercury-decide:free`) now, Jev (`~typesafe/jev-latest`) later via `DECISIONS_MODEL`; falls back to rules on failure. |
| VietOCR                       | Pretrained Vietnamese printed-text recognizer (`vgg_seq2seq`), exported as ONNX encoder/decoder and run with `ort`; paired with PP-OCRv6 text detection for receipts.                                         |
| Member                        | Person's role in one store: lead or seller, plus `can_enroll`. Proposed: each member links to exactly one Clerk user.                                                                                         |
| Clerk user                    | Proposed: person identity from Clerk (JWT `sub`). One Clerk user can be a member of several stores. _Avoid_: account, login.                                                                                  |
| PIN lock                      | Proposed: per-member PIN that locks the app on a shared phone before another member switches to their own Clerk session.                                                                                      |
| Assistant (trợ lý)            | Proposed: in-app chat agent that reads store data through assistant tools and drafts proposed actions. _Avoid_: chatbot, bot, AI.                                                                             |
| Assistant thread              | Proposed: one conversation between a member and the assistant; it is also the PostHog `$ai_session_id`.                                                                                                       |
| Assistant tool                | Proposed: named backend function the assistant may call, always with the caller's permissions. Read tools return data; propose tools create proposed actions.                                                 |
| Proposed action               | Proposed: write drafted by the assistant (stock adjustment, expense, price change, receipt confirm, debt entry, ...) that runs only after the member taps Confirm.                                            |
| Next-step strip               | Proposed: one horizontally swipeable row of next-step chips directly under the camera frame.                                                                                                                  |
| Next-step chip                | Proposed: one ranked, rule-based suggestion (no LLM call) that opens a screen or starts an assistant thread with a prefilled request.                                                                         |
| Daily digest                  | Proposed: once-a-day assistant summary of a store, cached per store and business date, shown as a card and sent as a push notification.                                                                       |
| Golden case                   | Proposed: Vietnamese request on the fixed eval store with expected tool calls, expected facts and a rubric.                                                                                                   |
| Golden set / smoke set        | Proposed: all golden cases (about 140) / the 25-case subset that runs on each PR.                                                                                                                             |
| Eval run                      | Proposed: one execution of the golden set against one model; recorded as PostHog score events plus a results file in the repo.                                                                                |
| Debt book (sổ nợ)             | Proposed: per-store ledger of what customers owe.                                                                                                                                                             |
| Customer                      | Proposed: person who buys on credit; name, optional phone, optional credit limit. Exists only for the debt book. _Avoid_: client, buyer.                                                                      |
| Credit sale (ghi nợ)          | Proposed: sale where all or part of the total is added to a customer's debt instead of being paid.                                                                                                            |
| Repayment (trả nợ)            | Proposed: customer payment against debt, by cash or transfer. Cash repayments count in chốt sổ expected cash.                                                                                                 |
| Telemetry contract            | Proposed: required span, log and product-event names and attributes; source of truth `docs/specs/assistant/telemetry-contract.md`.                                                                            |
| Telemetry environment         | Proposed: `deployment.environment.name` value: `production`, `test`, `eval` or `local`.                                                                                                                       |
| OTel Collector                | Proposed: Railway service that receives OTLP from backends and routes all traces and logs to PostHog.                                                                                                         |
| PostHog                       | Proposed: PostHog Cloud US project for product analytics, LLM analytics, logs, error tracking and session replay (ADR 0007).                                                                                  |
