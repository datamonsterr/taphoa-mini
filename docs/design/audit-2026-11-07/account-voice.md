## Findings

Counts are **3 major, 3 minor** distinct findings; these are confirmed differences, not an exhaustive count for the states marked unreachable.

1. **Major — Account adds visible blocks absent from board.** The capture shows `Đang dùng: Cô Ba`, a stock-threshold row, `Đọc to số tiền`, and a separate current-person row following the count row. The board goes straight from bank to elder mode and uses one people/count row (`docs/design/canvas/Account.dc.html:68`). The app renders these in `apps/mobile/src/features/account/AccountScreen.tsx:417`, `:462`, and `apps/mobile/src/features/account/DeviceSessions.tsx:170`; the caption is `apps/mobile/src/features/account/strings.ts:17`. DESIGN.md also describes some of these controls, so the board and written design disagree; resolve that source-of-truth conflict before removing functional controls. Proposed RNTL test `account_board_people_is_one_row`: with one session, assert `queryByTestId('account-session-0')` is null (if the board is authoritative).
2. **Major — Understanding omits the transcript.** Board `docs/design/canvas/VoiceListen.dc.html:55` shows the recognized sentence above the progress line. `apps/mobile/src/features/voice/VoiceSaleScreen.tsx:419` renders `UnderstandingView` without its transcript prop, and `UnderstandingView.tsx:44` renders the text only when supplied. The one-call backend returns the transcript with the draft, so current capture has no partial words to display; this is a design/implementation contract gap, not a fixture failure. Proposed RNTL test `understanding_shows_partial_transcript`: provide an available partial transcript during upload and assert `getByTestId('voice-transcript')` contains that text.
3. **Major — Android notification copy differs.** Board `docs/design/canvas/VoiceSystem.dc.html:32` says “Chạm nút nói trên màn hình để bán hàng.” The Android resource actually used by the foreground service at `apps/mobile/modules/voice-bubble/android/src/main/java/expo/modules/voicebubble/VoiceBubbleService.kt:232` is “Bấm nút nổi để bán hàng bằng giọng nói” (`apps/mobile/modules/voice-bubble/android/src/main/res/values/strings.xml:5`). Proposed Jest resource assertion `notification_body_matches_board`: assert the Vietnamese `voice_bubble_notification_text` equals the board sentence. Static only; no Android rendering was performed.
4. **Minor — SignIn starts 64 px too high on web.** Board logo top is y=80 (`docs/design/canvas/SignIn.dc.html:18`); app logo top is y=16 in the current 390×844 signed-out capture. The shared frame uses `space[4] + insets.top` (`apps/mobile/src/features/onboarding/kit.tsx:75`) and sign-in selects it at `apps/mobile/src/features/auth/SignInScreen.tsx:155`. Proposed Playwright test `sign_in_logo_top`: assert the logo bounding box y equals 80 at 390×844 with zero web safe-area inset.
5. **Minor — Welcome starts 56 px too high on web.** Board starts its content at y=72 (`docs/design/canvas/Welcome.dc.html:18`); the app's frame starts at y=16 (`apps/mobile/src/features/onboarding/WelcomeScreen.tsx:40`, `apps/mobile/src/features/onboarding/kit.tsx:75`). The lower actions have flexible spacing, so the displacement is not uniform. Proposed Playwright test `welcome_content_top`: assert the welcome frame content top padding is 72 px at 390×844 with zero web safe-area inset.
6. **Minor — Voice draft footer colors differ.** Board uses an accent microphone circle and unfilled surface check (`docs/design/canvas/VoiceSale.dc.html:102`); the captured draft shows a soft-grey microphone and green check. `apps/mobile/src/features/voice/VoiceMicButton.tsx:82` and `apps/mobile/src/features/voice/DraftView.tsx:224` select those colors. Proposed RNTL test `voice_draft_footer_colors`: assert idle microphone background is `colors.accent` and confirmation background is `colors.surface`.
