## Unavailable or mismatched requirements

- U12-02: the embedded camera article documents camera recognition and correcting a product, not the rubric's barcode fallback grid/manual-name flow. Do not invent missing buttons.
- U12-04: no embedded article or current mobile history/void screen provides the rubric's sale-history → select → void → reason flow. Returning that the help is unavailable is truthful but can miss the unchanged rubric.
- U12-05: current help/mobile flow is Account → invite by QR/code, with seller enrollment controlled separately. The rubric's invite role selector is unsupported. Keep the case, rubric and score.
- U14-03 (action, outside these 51): the real receipt_line_update payload stores quantity under new_values.quantity, while the unchanged case expects top-level quantity. The proposed receipt and line can be correct and still miss this scorer. No payload or scorer hack is included.

## Judge validation

The judge model and pass score stay fixed. The accepted input adds the user messages and fixture context, including actual persisted tool messages from the final assistant turn scoped to the eval store and thread. The same serializer is used for calibration; original calibration examples lack user messages/tool evidence, so those fields remain absent or empty. Calibration labels and rubrics are unchanged. See [judge calibration](judge-calibration.md).

An intermediate context version had only partial oracle assertions; the judge treated these as exhaustive and rejected valid extra tool values. That 36-case iteration is diagnostic only. Actual tool evidence was added before the accepted full run.
