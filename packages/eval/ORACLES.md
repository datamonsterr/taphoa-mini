# Oracle catalog

Every expected fact of the golden set comes from one of these oracles, never from a typed number. Generated by `node src/cli.ts oracles --md` against the eval store (business date 2026-10-20); do not edit by hand. The SQL lives in `src/oracle/queries/<name>.sql`.

## Using an oracle

- A fact names the oracle and its args: `{"oracle": "sales_revenue", "args": {"period": "yesterday"}, "match": "number"}`. `expect_action` fields use `{"oracle": ..., "args": ...}` or `{"ref": ...}` the same way.
- Money is integer dong. Business dates and times are Asia/Ho_Chi_Minh. Counts of products are in base units.
- Product names in answers of kind names are display names: the injection product shows without its injected tail, so no canary string reaches a fact.
- The scorers match names and numbers in the answer. They cannot match dates or times, so oracles that return them are for rubrics and the judge.
- Top-N oracles return exactly N names. Pick N, and a period, so the Nth and the next product do not tie.
- Lead-only figures (cost, margin, gross profit, member activity, day close, review queue, recognition, supplier costs) are the denied facts of seller cases: put the same oracle in `denied_facts`. The oracles listed under PERM below give extra numbers for that.
- U23 (debts) has no oracle yet; it waits for X5.

## Args

The store id and the business date are always bound first (`$1`, `$2`); declared args follow in header order.

| Type               | Accepts                                                                        |
| ------------------ | ------------------------------------------------------------------------------ |
| `text`             | Any text, bound as it is.                                                      |
| `int`              | A whole number.                                                                |
| `date`             | `today`, `yesterday` or an ISO date such as `2026-10-14`.                      |
| `period`           | A period (below). It takes two SQL placeholders: its first and its last date.  |
| `product`          | The exact catalog name of a product. It must exist.                            |
| `member`           | The display name of a member (`Cô Ba`, `Bé Na`, `Anh Tư`).                     |
| `category`         | The name of a catalog category. It must exist.                                 |
| `supplier`         | The name of a supplier of a confirmed receipt, as `supplier_names` returns it. |
| `expense_category` | One of `nhap_hang`, `dien`, `nuoc`, `khac`, `all`.                             |

Periods resolve against the pinned date (2026-10-20 is a Tuesday):

| Period         | From       | To         |
| -------------- | ---------- | ---------- |
| `today`        | 2026-10-20 | 2026-10-20 |
| `yesterday`    | 2026-10-19 | 2026-10-19 |
| `this_week`    | 2026-10-19 | 2026-10-25 |
| `last_7_days`  | 2026-10-14 | 2026-10-20 |
| `prev_7_days`  | 2026-10-07 | 2026-10-13 |
| `last_14_days` | 2026-10-07 | 2026-10-20 |
| `last_30_days` | 2026-09-21 | 2026-10-20 |
| `last_week`    | 2026-10-12 | 2026-10-18 |
| `prev_14_days` | 2026-09-23 | 2026-10-06 |
| `prev_30_days` | 2026-08-22 | 2026-09-20 |
| `this_month`   | 2026-10-01 | 2026-10-31 |
| `last_month`   | 2026-09-01 | 2026-09-30 |
| `this_quarter` | 2026-10-01 | 2026-12-31 |
| `last_quarter` | 2026-07-01 | 2026-09-30 |
| `year_to_date` | 2026-01-01 | 2026-10-20 |

Also an ISO date (`2026-10-14`), a range (`2026-10-12..2026-10-18`) or a month (`2026-09`). `this_week` runs Monday to Sunday (2026-10-19..2026-10-25), `last_7_days` counts today and the six days before it.

## Refs

A ref points at a row. The harness resolves it to an id before it scores an action.

| Ref                               | Resolves to                                                                                                                                                                      |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `product:<exact name>`            | `products.id`                                                                                                                                                                    |
| `member:<display name>`           | `members.id`                                                                                                                                                                     |
| `category:<name>`                 | `categories.id`                                                                                                                                                                  |
| `receipt:draft`                   | The draft receipt (the eval store has one).                                                                                                                                      |
| `receipt:last`                    | The newest confirmed receipt.                                                                                                                                                    |
| `receipt:<supplier>@<YYYY-MM-DD>` | The confirmed receipt of that supplier on that date. Supplier codes: `HT` (Đại lý Hưng Thịnh), `MP` (Công ty Minh Phát), `BS` (Sỉ Bà Sáu chợ Bình Tây); the full name works too. |
| `receipt_line:<receipt key>#<n>`  | `receipt_lines.id` of line n, counted from 1 as in STORE.md (`receipt_line:draft#8` is the unmatched line).                                                                      |
